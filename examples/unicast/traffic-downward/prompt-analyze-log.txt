As an IoT expert specializing in Contiki-NG, please write a Python script to analyze a log file generated from a network test. The script should parse specific information to calculate the Packet Reception Rate (PRR) and Latency for unicast communication.

 **Test Scenario:**
 
 * A single sender node (ID: 1) is sending unicast messages to 20 receiver nodes (IDs ranging from 2 to 21, inclusive).
 * The log file contains entries from both the sender and the receivers.
 
 **Log Format:**
 
 * **Sender Log:** Each time the sender (ID: 1) transmits a new message, a log entry is generated with the following format: `"(HH:mm:ss.SSS or mm:ss.SSS)  ID:1 Send to node ID:{receiver_id}, address is {ipv6_address} and packet_number #{packet_number}"`. For example: `"04:39.767  ID:1 Send to node ID:17, address is fd00::211:11:11:11 and packet_number #55"`.
 * **Receiver Log:** Each time a receiver node (ID: 2-21) receives a message, a log entry is generated with the following format: `"(HH:mm:ss.SSS or mm:ss.SSS)    ID:{receiver_id} Received from Root with message: 'Send from Root (ID:1) with packet_number {packet_number}', total_received {total_received_count}"`. For example: `"04:39.768    ID:17 Received from Root with message: 'Send from Root (ID:1) with packet_number 55', total_received 51"`.
 
 **Your Tasks:**
 
 1.  **Parsing and Data Extraction:**
     * Iterate through the log file and identify log entries from the sender and the receivers.
     * For each sent message, extract the `packet_number` and the `send_time` (in `(HH:mm:ss.SSS or mm:ss.SSS)` format). Store this information, associating it with the intended receiver ID.
     * For each received message, extract the `packet_number`, the `receive_time` (in `(HH:mm:ss.SSS or mm:ss.SSS)` format), the receiver's `ID`, and the `total_received` count.
 
 2.  **Latency Calculation:**
     * For each successfully received packet, calculate the latency (delay) by subtracting the `send_time` from the `receive_time`. Ensure the latency is calculated in milliseconds. You will need to convert the time strings to a comparable numerical format (e.g., total milliseconds from the start of the log or using appropriate Python time handling).
     * Store the calculated latencies for each receiver node in a list to allow for average latency calculation (though the current output format asks for individual latencies).
 
 3.  **PRR Calculation:**
     * Determine the total number of messages sent by the sender (ID: 1). This will be the largest `packet_number` found in the sender's logs.
     * For each receiver node, determine the total number of messages received. This will be the largest `total_received` value recorded for that specific receiver.
     * Calculate the Packet Reception Rate (PRR) for each receiver using the formula: `PRR = (total_message_received / total_message_sent) * 100`.
 
 4.  **Output Formatting:**
     * Present the results in the following comma-separated format:
 
     ```
     ID, total_message_received, PRR, receive_time, send_time, Latency
     2, 60, 74.42%, 1591027, 1592650, 796.12 ms
     3, 28, 50.00%, 1591027, 1592650, 760.00 ms
     ...
     20, 28, 50.00%, 1591027, 1592650, 760.00 ms
     ```
 
     * **Important Notes for Output:**
         * The `ID` column refers to the receiver node's ID (from 2 to 21).
         * `total_message_received` is the largest `total_received` value for that receiver.
         * `PRR` should be formatted as a percentage with two decimal places (e.g., `74.42%`).
         * `receive_time` and `send_time` in the output should ideally be a numerical representation of the time for easier analysis (e.g., total milliseconds from the start of the log, or a Unix timestamp if applicable, though the example shows seemingly arbitrary large numbers - clarify the desired format if needed). If not easily convertible to a single number, keep the original `(HH:mm:ss.SSS or mm:ss.SSS)` format.
         * `Latency` should be the calculated delay in milliseconds, formatted to two decimal places (e.g., `796.12 ms`). If a packet was sent but not received, you can indicate the latency as `N/A` or omit the entry from the latency calculation for that specific packet in the output.
         * Example for the time format ((HH:mm:ss.SSS or mm:ss.SSS)): 53:18.558 means HH = 0, mm = 53, ss = 18, SSS = 558; 1:02:18.558 means HH = 1, mm = 02, ss = 18, SSS = 558
         * Include a final line in the output showing the total number of messages sent by the sender: `total_message_sent = {largest_packet_number_sent_by_ID_1}`.
 
 **Hints for Implementation:**
 * Analyze log from 01:00.000 (mm:ss.SSS) (means that after 60 seconds the sender will send packet).
 * Consider using regular expressions (`re` module in Python) to efficiently parse the log lines and extract the required information.
 * Use dictionaries to store and organize the extracted data, for example, to map packet numbers to send times and to store received information for each receiver ID.
 * Pay close attention to time conversions when calculating latency. You might need to convert the `(HH:mm:ss.SSS or mm:ss.SSS)` format into a numerical representation (e.g., seconds or milliseconds since the start of the log) to perform the subtraction.
